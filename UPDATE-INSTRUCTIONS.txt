BYZANTINE EMPIRE WEBSITE V5.8.5 — PORTAL START + REFRESH REPAIR

UPDATE-ONLY FOR YOUR EXISTING ByzantineEmpireWebsite GITHUB REPOSITORY.

INSTALL
1. Extract this ZIP.
2. Copy index.html, 404.html and the _next folder into the ROOT of your
   existing repository, overwriting matching files and merging _next.
3. Commit and Push origin in GitHub Desktop.
4. Wait until GitHub Pages deploys; open the canonical link:
   https://YOUR-GITHUB-USERNAME.github.io/ByzantineEmpireWebsite/
5. Hard-refresh (Ctrl+Shift+R). Test with a fresh tab too.

FIXES
- Prevents scrolling and menu navigation from rewriting the address bar to
  /projects and other subpaths that GitHub Pages cannot serve on refresh.
- Normalizes old deep paths to /ByzantineEmpireWebsite/ at app startup.
- Uses the original Portal (landing) scene when a route is invalid.
- Ensures scroll starts at 0 on a fresh homepage entry before the experience
  overlay is dismissed.
- Includes 404.html as a fallback for previously bookmarked deep URLs.
- Preserves no-scroll-back from crystals to portal; Portal menu still works.
- Leaves the crystal, mountain, images, portal shader, and morphing unchanged.

NOTE
The address bar intentionally remains on /ByzantineEmpireWebsite/ while
visitors navigate between the site's internal scenes. This is how the current
single-HTML GitHub Pages deployment avoids refresh 404s.
